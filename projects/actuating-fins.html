Rocket Controls

Active Rocket Roll Control

Designing and building a subscale rocket to demonstrate active roll control using servo-actuated canards.

Ongoing Project
Current stage: First full-vehicle CAD iteration

What I'm building

The goal is to build a subscale rocket that can actively control roll using four servo-actuated canards. I'm intentionally keeping the first version to roll control instead of trying to solve roll, pitch, and yaw all at once. Even with that narrower goal, I still have to work through the full chain: vehicle layout, actuator sizing, mechanical packaging, avionics and controls integration, bench testing, and eventually flight testing.

How the project got here

This project originally started with servo-actuated tabs built into the rocket's main fins. I worked on the OpenRocket vehicle model, servo sizing, aerodynamic loading and torque calculations, fin geometry, CAD, 3D printing, and a few physical prototypes.

One practical issue we had not finished solving was serviceability. The servo sat inside the fin, so we needed a way to remove and reuse it after the fin was assembled. We discussed a removable casing or access feature, but the project changed direction before we developed that idea into a final design. The work later moved toward fully actuated surfaces and then toward the current canard-based demonstrator.

An early lesson in overbuilding

One prototype fin was printed with an internal lattice, and I let epoxy seep into the structure to see how that manufacturing approach would turn out. It became extremely rigid and also extremely heavy—basically a brick. That much mass low on the rocket would have shifted the vehicle's center of gravity significantly downward.

It was never load tested, aerodynamically tested, or flown. I only manufactured it to evaluate the idea physically, but it was a useful reminder that making one part stiffer can create a much bigger problem for the vehicle.

Current design

The current vehicle is a subscale rocket with four forward servo-actuated canards and four stationary aft fins. The active control is focused on roll. Onboard sensing and control hardware are planned, and the avionics and recovery hardware still have to fit inside the same overall vehicle layout.

I originally looked at using two canards because fewer servos obviously makes the hardware easier. I moved to four because the symmetric layout gives the controller more useful authority when the rocket experiences an off-axis angle of attack.

Packaging also changed the size of the rocket. An earlier concept used an airframe around 2.6 inches in diameter. Once I put the actual servos into CAD, fitting everything inside that airframe stopped looking practical, so I reworked the vehicle around the hardware it actually needs to carry.

The first full-vehicle CAD model is complete at the external-architecture level. The nose, airframe, four forward canards, and four aft fins are modeled. The canard attachments and internal bay are not finished yet; I'm waiting on some dimensions before I can finalize those parts.

Where I'm at now

The overall vehicle layout is in place, and I'm now working through the mechanical details that connect the canards to the rest of the rocket.

Completed so far

  • Defined the project scope and roll-control objective
  • Established the initial vehicle architecture
  • Worked through the two-vs.-four-canard decision
  • Completed servo downselection and sizing work
  • Developed the OpenRocket vehicle model
  • Built the first full external vehicle CAD assembly

Currently working on

  • Canard attachment and interface
  • Canard bay and internal packaging
  • Detailed mechanical CAD
  • Overall vehicle integration

What comes next

  • Manufacture the mechanical hardware
  • Bench-test the canard actuation
  • Integrate the sensing and control electronics
  • Validate IMU roll-rate measurement
  • Run closed-loop bench testing
  • Complete system-level testing
  • Conduct an eventual subscale flight test

So far, the biggest lesson has been how quickly packaging becomes real once the actual hardware enters CAD. A mechanical idea can work well by itself and still create a vehicle-level problem. Keeping the scope to roll control makes the project more testable, and modeling the full rocket early is helping me find integration problems before I start manufacturing parts.
